# 챗봇 지식자료

2026-10-30 사용자 제공 Markdown과 DOCX를 확인했습니다. 두 문서는 같은 지식자료이며, 중복 답변을 막기 위해 Markdown을 검색 원본으로 사용합니다. DOCX는 검토 원본으로 보관합니다.

- 원본: `maryeye_chatbot_knowledge.md`, `maryeye_review.docx`
- 색인: `node qa-index.cjs` → `dist/qa-data.json` (기존 25개 및 FAQ 43개, 총 68개)
- 검증: `node --test chatbot.test.cjs knowledge.test.cjs faq.test.cjs`

`qa-index.cjs`는 Markdown 문단과 FAQ의 출처 행 번호를 보존하고, 검색에 사용할 질문 표현을 부여합니다. 답변 원칙과 자료 관리 문구는 일반 검색 답변에서 제외합니다. 응급 증상 문단은 별도 우선 분기에서 사용합니다. 의료 참고 링크는 답변 근거에 표시됩니다.

기존 `img/qa.txt`의 10시 진료 시작 안내는 더 이상 사용하지 않습니다. 새 자료의 평일 09:00~18:00, 토요일 09:00~13:00을 사용합니다. 특정 날짜 운영, 실제 예약 상태, 확정 가격은 추측하지 않습니다.

수정 후 `node qa-index.cjs`로 정적 자료를 갱신하세요. 실행 중인 Node 서버는 원본을 요청마다 읽지만, 색인/검색 코드 변경 시에는 서버를 재시작해야 합니다. 자료만으로 모델을 재훈련하지 않으며, 검색된 근거로 답변합니다. 자료 갱신 시 검색용 별칭과 테스트도 함께 확인하세요.

## 자연스러운 질문과 답변

`clinic-profile.json`은 현재 홈페이지에 표시된 세 명의 전문의 이름과 인원을 담습니다. 의료진 변경 시 홈페이지와 이 파일을 함께 수정하세요. Markdown에는 의료진 인원이 없으므로 이 현황 파일을 별도 근거로 사용합니다.

브라우저와 서버는 ‘원장님 몇분계셔’, ‘주차돼?’, ‘토욜 몇시까지야’ 같은 핵심 표현으로 의도를 파악합니다. 여러 질문은 확인된 사실을 조합해 답하며, 실제 날짜별 진료 일정은 확정하지 않습니다.

서버에 `OPENAI_API_KEY`와 `OPENAI_MODEL`이 설정된 경우 근거와 초안을 Responses API로 보내 자연스러운 답변 문장과 근거 ID를 함께 받습니다. 키·모델이 없거나 API 실패, 잘못된 출처, 근거 없는 숫자가 반환되면 로컬 답변을 사용합니다. 응급 안내는 모델 호출보다 먼저 처리합니다. 생성형 API가 없는 정적 호스팅에서도 로컬 의도 파악과 문장 조합이 동작합니다.

구현 참고: [OpenAI 공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

## 안과 자주 묻는 질문 43개

`faq-catalog.cjs`에서 질문·유사 표현·필수 키워드 그룹·답변·출처를 관리합니다. `node qa-index.cjs` 실행 시 검토용 `clinic-faq.md`와 정적 색인에 함께 반영됩니다. 일반적인 진료 준비, 검사, 백내장·노안, 드림렌즈, 소아안과, 안구건조, 녹내장, 망막, 안성형, 비용·서류를 다룹니다.

응급 분기 → 구체적인 FAQ → 병원 안내 의도 파악 → 일반 자료 검색 순으로 처리합니다. 예를 들어 ‘백내장 수술 후 안경’ 질문에 백내장 정의만 답하지 않고 수술 후 안경 FAQ를 선택합니다. 진료시간·주차 등과 함께 물으면 확인된 안내를 덧붙입니다. 원본 질문과 유사 표현, 응급 우선순위, 복합 질문, 미확정 정보를 테스트합니다.

새로운 일반 의료 정보는 해당 항목의 NEI 참고 출처를 확인해 작성했습니다. 병원별 준비물·금식·렌즈 중단 기간·접수 마감·예약 현황은 정해진 사실을 만들지 않고 병원에 확인하도록 안내합니다. FAQ 변경 시 `faq-catalog.cjs`를 수정하고 색인을 갱신한 뒤 서버를 재시작하세요.
