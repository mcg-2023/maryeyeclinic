# 주례성모안과 홈페이지

제공된 「주례성모안과 홈페이지 리뉴얼 기획안」을 참고한 반응형 정적 홈페이지입니다.

- 메인 9개 섹션, 5개 대분류 메뉴, 19개 상세페이지
- HTML 본문, 페이지별 제목·설명·canonical, 사이트맵
- 메가메뉴, 모바일 하단 퀵메뉴, 메인 비주얼 선택, 장비 슬라이더
- 의료진 소개, 진료시간, 지도 연결, 주소 복사, 사진 확대, FAQ
- 비급여 안내 팝업

## 실행과 변경

Node.js 24 이상이 필요합니다. 최초 실행 전 `npm.cmd install`로 제공된 관리자 키트와 의존성을 설치합니다.

```sh
node build.cjs
node check.cjs
node server.cjs
```

미리보기: http://127.0.0.1:4173

## 눈여겨볼 정보 관리자

관리자: http://localhost:4173/admin/ · 새 글: http://localhost:4173/admin/new/

제공된 `page-manager-kit-v1.2.0-clinic.6`을 연결했습니다. 제목·주제·요약·본문·작성자를 입력하고 대표이미지를 선택한 뒤 임시저장 또는 발행할 수 있습니다. 발행한 글만 `/interest.html`과 `/articles/글ID/`에 표시됩니다. 기존 13개 안내 글도 첫 실행 시 한 번 가져와 수정·보관·삭제할 수 있습니다. 게시판 검색에는 새 글의 제목·요약·본문이 자동 반영됩니다.

글과 이미지는 `website/.data/posts.sqlite`에 저장됩니다. 브라우저를 닫거나 서버를 다시 실행해도 유지됩니다. 백업할 때는 서버를 종료하고 `.data` 폴더 전체를 복사하세요. DB는 Git과 정적 배포 파일에 포함하지 않습니다. `npm run build`는 DB를 초기화하지 않습니다.

현재 루프백 로컬 미리보기에서는 키트의 로컬 관리자 모드로 열립니다. 외부 공개 운영은 별도 서버 배포와 관리자 인증 설정이 필요합니다. GitHub Pages 같은 정적 호스팅만으로 글 저장 기능은 실행되지 않습니다. 키트의 운영 배포 안내는 제공 폴더의 `Vercel-Supabase-배포안내.md`에 있습니다. 이 작업에서는 외부 DB나 운영 사이트에 배포하지 않았습니다.

관리자 설정은 `page-manager.config.cjs`, 서버와 공개 게시판 연결은 `page-manager.cjs`에서 관리합니다. 키트 원본은 수정하지 않았습니다. 검증: `node --test page-manager.test.cjs`.

`dist/app.js`의 CONFIG에서 선택형 진료 배너, 상담·예약 링크, 비급여 항목을 변경할 수 있습니다.
의료진과 진료 문구는 같은 파일에서 변경한 뒤 `node build.cjs`를 실행하세요.
`template.html`은 공통 헤더·푸터, `dist/styles.css`는 반응형 스타일입니다.
외부 링크는 확인된 HTTPS 주소만 사용하세요.

## 확인이 필요한 자료

- 다른 두 분의 의료진 이름·원본 사진·세부 약력 및 담당 분야 확정
- 3인 단체 사진 또는 각 프로필 사진을 이용한 첫 화면
- 카카오톡 채널, 네이버 예약, 온라인 상담의 실제 연결 주소
- 확정된 비급여 가격표, 병원 개인정보처리방침
- 주차 안내와 최신 진료시간 확인
- 브랜딩북 원본 및 랜딩페이지용 눈 구조 일러스트
- 기존 홈페이지 URL 매핑과 리디렉션 정책

미확인 의료진 정보와 금액은 임의로 작성하지 않았습니다.
PPT의 저해상도 프로필 자료는 텍스트 영역을 CSS로 제외하고 사용했습니다.
정식 운영 전 원본 사진과 병원 확인 문구로 교체해 주세요.

현재 Sites 게시본은 소유자 전용 비공개입니다.

## 메인 QA 챗봇

`knowledge/maryeye_chatbot_knowledge.md`를 근거로 한국어 질문을 검색하는 챗봇을 메인에 추가했습니다. 검색은 한국어 두 글자 단위 토큰, IDF 가중치, 진료시간 표현 정규화를 사용합니다. 검색 결과의 원문과 파일·행 번호를 답변 근거로 표시합니다. 자료에 없는 조건은 전화 문의로 안내합니다.

현재는 2026-10-30 사용자 제공 Markdown과 DOCX를 확인한 지식자료 24개 항목을 사용합니다. 두 파일의 내용이 같아 Markdown을 검색 원본으로 사용하고 DOCX는 검토 원본으로 보관합니다. 기존 qa.txt의 오전 10시 안내는 사용하지 않으며 새 자료의 평일 09:00~18:00, 토요일 09:00~13:00 안내를 사용합니다. 갱신 방법은 [knowledge/README.md](knowledge/README.md)를 참고하세요.

QA는 현재처럼 질문 한 줄과 답변을 쓰거나 다음 형식으로 추가할 수 있습니다. 항목 사이에 빈 줄을 넣고, 다중 행 답변도 사용할 수 있습니다.

```text
Q: 주례성모안과 진료시간
A: 오전 10시부터 오후 6시
```

`node build.cjs` 실행 시 `dist/qa-data.json`이 갱신됩니다. 정적 배포에서도 브라우저가 이 파일을 검색해 원문 답변을 제공합니다. 정적 호스팅에서는 QA 변경 후 재빌드·배포가 필요합니다. `node server.cjs`로 실행한 서버의 `/api/chat`은 질문마다 QA 원본을 읽으므로 수정이 바로 반영됩니다.

### 생성형 RAG 설정

기본 모드는 외부 API 없이 질문의 핵심 표현을 파악해 확인된 사실을 자연스러운 문장으로 조합합니다. 원장님·의사 선생님 같은 표현과 짧은 말투, 복합 질문을 지원합니다. 일반 검색 답변도 함께 사용합니다. 서버 환경변수 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 모두 설정하면 OpenAI Responses API를 사용하는 `rag` 모드가 활성화됩니다. 모델은 검색된 근거로 답변 문장을 작성하고 근거 ID를 함께 반환합니다. 존재하지 않는 출처, 근거 없는 숫자, API 실패, 제한 시간 초과 시 로컬 답변을 사용합니다. 자료 없는 질문은 모델에 보내지 않습니다. 상세 설정은 [knowledge/README.md](knowledge/README.md)를 참고하세요.

```sh
# .env.example을 .env로 복사한 뒤 서버에서만 키와 모델을 설정
node build.cjs
node --env-file=.env server.cjs
```

키는 HTML·브라우저·정적 배포 파일에 넣지 않습니다. 서버는 이번 질문과 검색된 QA만 외부 API에 보내며 `store: false`를 사용합니다. 개인정보처리방침의 챗봇 안내도 수정했습니다. Node.js 22 이상이 필요하며, `.env`는 Git에서 제외합니다. 외부 API 연결에는 사용 가능한 모델과 API 키가 필요합니다. 생성형 모드는 정적 Sites 호스팅만으로 실행되지 않으며 이 Node 서버 또는 동일한 `/api/chat` 기능을 제공하는 서버 배포가 필요합니다.

API 구현 참고: [OpenAI 공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

검증: `node --test chatbot.test.cjs`, `node check.cjs`. 대화 저장·진료 예약·환자 정보 수집 기능은 포함하지 않습니다.
